# L2.4: questions for the builder

L2.4 (draw-in) is green. Eight new behaviors cover `draw`: `steps.md` B36
to B43, under a fuller R8. The untagged spike check is gone; its two
assertions are now B36 and B39. Six behaviors describe what v0.1 already
did. Two found bugs, and both are fixed:

- **A box's sides all drew at once.** Excalidraw strokes every line
  twice, each pass a subpath of one path. A dash pattern starts again at
  each subpath, so every side of a box drew at the same time, in about an
  eighth of the box's turn, and then held still. Each line is now a path
  of its own, drawn in turn, so a box draws one side after another (B39).
- **The draw-in ended on a pause.** The invisible element that carries
  the font's glyphs took the last turn, so the diagram was finished before
  the first step began. Invisible elements now take no turn, and the last
  element finishes as the first step starts (B38).

The deploy example's SVG changes only in its draw-in; everything from the
first step on is byte-identical. It grows from 63 KB to 105 KB, because
each line now carries its own animation. Bundt's flows don't use `draw`
and still render.

The checks render a small scene of their own, with `draw: 2` and without,
and compare each element's pixels on screen, moment by moment, with how it
looks fully drawn. Eleven deliberate breaks were each caught:

- the glyph carrier taking a turn again
- lines not split, so a box's sides draw at once
- elements drawn in reverse order
- strokes faded rather than drawn
- fades that jump rather than fade
- dashed strokes drawn rather than faded
- `draw: true` lasting 2 s
- the camera starting from the last step's view
- elements shown before their turn
- elements finishing early
- every element drawn at once

## 1. The draw-in on every loop (`steps.md` R8, B43)

The draw-in plays at the start of every loop, not only the first. The SVG
has one clock (`svg.md`), and the loop is the whole animation, draw-in
included. The GIF and videos are frames of that same loop.

- (a) **Every loop** (recommended). This is what v0.1 does. A diagram that
  rebuilds itself each time reads as the start of the story, and each
  output format plays the same loop.
- (b) Only the first time. The steps would then loop on their own after
  one draw-in. This needs a second clock in the SVG, and a GIF or video
  would show the draw-in once and then the steps on repeat.
