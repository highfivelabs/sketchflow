# L1: questions for the builder

L1 Shape is green: every check passes. Its 20 new behaviors wait on these
answers before their checks are frozen.

## 1. Confirm the L1 behaviors

`scene.md` B1 to B9 restate what v0.1 already did when reading a diagram,
and all nine passed before any code changed. One wording changed: a name
two shapes share now lists their ids (`"twin" names 2 shapes (left,
right)`), where v0.1 said only "use an element id".

`flow-file.md` B7 to B17 are new: v0.1 checked only `scene`, `steps` and
captions, and let any other mistake through to a crash or a silent
default. Now:

| Behavior | What a mistake does |
| --- | --- |
| B7 to B9 | An unknown key names itself and where it is: `step 2, flow 1: unknown key colour` (your answer to `asks/L0.md` 2) |
| B10 to B13 | A value of the wrong kind names the key and the kind it must be: `typing must be a number` |
| B14, B15 | A flow needs a path of two or more shapes; a badge and a note need `at` and `text` |
| B16 | The whole flow, names included, is checked before Chrome opens, so a mistake fails at once and writes nothing |
| `scene.md` B7, B8 | A name error says where the name is: `step 2, flow 1: no shape "registy"` |

B17 holds the other side: a flow using every key in the README's tables
still renders. The deploy example's SVG is unchanged, byte for byte, and
bundt's two flows still render.

**Recommended:** confirm all 20 as written.

## 2. `from` and `to` in a flow

v0.1's code took `{from: a, to: b}` as another way to write `path: [a, b]`.
The README never mentioned it, and no flow we have uses it.

- (a) **Drop it** (recommended): `from` is now an unknown key. One way to
  write a flow, and `path` already covers it. This is what the code does now.
- (b) Keep it as a documented shorthand.

## 3. One mistake, or all of them

A flow with several mistakes reports the first one and stops.

- (a) **The first only** (recommended for now): the message stays one
  line, and the next run shows the next mistake.
- (b) Every mistake, one per line: fewer runs for an agent fixing a long
  flow, at the cost of more code to keep each check independent.
