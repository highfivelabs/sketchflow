# L2.1: questions for the builder

L2.1 (flows and `via`) is green. Seven new behaviors say which way a token
goes: `steps.md` B13 to B19, and `flow-file.md` B18. Five of them describe
what v0.1 already did. Two found bugs, and both are fixed:

- **A path of three or more shapes cut corners.** Where one hop's arrow
  ended and the next one started from another side of the shape, the
  token dropped the next arrow's first point. So it went diagonally from
  where it entered the shape to the next arrow's second point. It now runs
  across the shape, from where it enters to where it leaves (B13). The
  deploy example is unchanged, because its shapes are in a line. Bundt's
  `bntd → outpost → fetcher` paths will look different the next time they
  are rendered.
- **`via` on a path of three shapes was silently ignored.** It is now an
  error (`flow-file.md` R15, B18).

The checks render a small scene of their own and read the trails from the
SVG. They watch the label in Chrome. Seven deliberate breaks were each
caught by the check meant for them:

- tokens aimed from shape centers rather than edges
- `via` bends taken in reverse
- the start aimed at the far shape rather than the first bend
- an arrow winning over `via`
- an arrow bound at one end being followed
- the label left behind while the token moves
- the default color changed

## 1. Curved arrows (`steps.md` A3)

Excalidraw draws an arrow with "round" corners as a curve through its
points. A token follows the points with straight segments, so on a curved
arrow with bends it would cut inside the curve.

I counted the arrows in bundt's diagrams (22 files) and the deploy
example. Every rounded arrow has exactly two points, which makes it a
straight line, and so the token is exact. Every arrow with bends is drawn
sharp. So the gap does not show up in any diagram we have.

- (a) **Keep straight segments** (recommended). Keep the README's Limits
  note, and come back to this if a real diagram needs it.
- (b) Follow the curve. This means rebuilding Excalidraw's curve from its
  points, which ties us to how Excalidraw draws curves.

## 2. `via` where an arrow is drawn (`steps.md` R4, B16)

R4 used to say that a hop follows the drawn arrow, and only "without one"
follows `via`. The code has always done the opposite: `via` wins. R4 and
B16 now say what the code does.

- (a) **`via` wins** (recommended). Writing `via` is a choice to route
  around something, and it would be useless if any arrow overrode it.
- (b) The arrow wins, and `via` there is an error.

## 3. Arrows bound at one end (`steps.md` B17)

A hop follows only an arrow whose two ends are both bound to its shapes.
Excalidraw binds an end when you drop it on a shape. An arrow that only
*touches* a shape, or that is bound at one end, is passed over, and the hop
runs straight.

- (a) **Bound at both ends only** (recommended). This is what v0.1 does,
  and nothing has to be guessed. If a token runs straight where you
  expected it to follow an arrow, re-drop the arrow's ends in Excalidraw.
- (b) Also follow an arrow whose loose end comes within a few pixels of
  the shape.
