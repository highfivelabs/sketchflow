# L1.5: questions for the builder

**Answered 2026-11-27.** L1.5's behaviors are confirmed and its checks frozen.

L1.5 Timeline is green, and no code changed: v0.1's timing already does
what the twelve new behaviors say. The checks pause the real SVG in
Chrome and seek it. To show they can fail, six deliberate breaks to the
timing code were each caught by the check meant for them: notes ignoring
`keep`, tokens starting before the camera arrives, tokens overlapping, a
badge appearing early, no pause at a step's end, and a jump at the loop.

## 1. Confirm the L1.5 behaviors

`steps.md` B1 to B12:

| Behavior | When |
| --- | --- |
| B1, B2 | A step lasts 3 s by default, or its `seconds` |
| B3, B4 | ...and always long enough to type its caption, move its tokens and write its notes, plus at least 1 s |
| B5, B6 | `zoom` moves the camera for 0.9 s and then holds it; a step without `zoom` keeps the camera where it was |
| B7 | Without `draw`, the loop has no jump: it ends where it begins |
| B8, B9 | Tokens wait for the camera, and run one after another |
| B10, B11 | Badges and notes come after the last token; a note with `when: start` comes before |
| B12 | A note is gone when its step ends, unless `keep: true` |

**Recommended:** confirm all 12 as written.

Answer (Brandon, 2026-11-27): confirmed, all 12 as written. Frozen:
`test/l1_5-steps.test.js`.

## 2. How the loop closes (`steps.md` R2)

R2 used to say the camera "returns to where the first step began" at the
end of the loop. The code does something slightly different: the loop
**starts** from where the last step left the camera, and the first step
eases from there to its own view. So there is no jump, and no extra time
at the end. R2 now says what the code does.

- (a) **Keep it as it is** (recommended): no added time. The first frame
  of the loop shows the last step's view, but it moves at once.
- (b) Add a 0.9 s return at the end of the last step, so the loop starts on
  the first step's view. The first frame is better as a still (a README
  poster), at the cost of 0.9 s a loop.

Answer (Brandon, 2026-11-27): (a), keep it as it is.

## 3. The pauses are look, not contract (`steps.md` A2)

The behaviors hold the pauses to "at least" and not to exact numbers:
the 2.2 s hold after a step's last token, the 1.6 s after its caption, and
the 0.3 s before its tokens start. That way the look can be tuned without
unfreezing checks. The two documented numbers, 3 s and 0.9 s, are held
exactly.

- (a) **Yes** (recommended): the pauses can change in any release.
- (b) No, hold the exact numbers, so a rebuild of our public docs never
  changes their pacing without an unfreeze.

Answer (Brandon, 2026-11-27): (a), yes: the pauses are look.
